1. What's New & What Changed

We transitioned from a strict keyword-based text search to an AI-powered Semantic Search. This allows users to find jobs based on the meaning of their query, rather than exact text matches.

Component What Changed How & Why
Domain Models
Ad.java & Cv.java		 Added List<Double> embedding Vectors (arrays of floating-point numbers) represent the AI's understanding of the text. Storing these in the DB allows MongoDB to index and search them. Added a non-persisted matchScore to hold query results.
Data Transfer Object
AdDto.java		 Added Double matchScore Allows the backend to pass the calculated relevance percentage (e.g., 0.95 = 95%) directly to the frontend templates.
AI Integration

On Search: Intercepts keyword queries, generates a vector for the query, and runs a $vectorSearch pipeline. Includes a Zero-Downtime Fallback that reverts to standard keyword search if the AI API fails.
Frontend UI
result.ftl		 Added Match Badge If a matchScore is present in the DTO, it renders a green badge: ⭐ AI Match: 95% next to the job title.

3. Setup Tutorial: API Keys & MongoDB Atlas

Step 3.1: Getting your NVIDIA NIM API Key

NVIDIA NIM provides access to state-of-the-art embedding models. Here is how to configure them:

  1. Go to build.nvidia.com and log in.
  2. Filter the models by Use Case > Text-to-Embedding (as shown in your first image).
  3. Select an embedding model. By default, the code uses snowflake/arctic-embed-l. If you prefer to use nemotron-3-embed-1b (from your screenshot), you can change the "model" string in AiService.java line 51!
  4. Click on "Get API Key" in the top right corner of the dashboard to generate a key starting with nvapi-....
  5. Set this key as an Environment Variable on your server:
    # On Windows (Command Prompt)
    setx NVIDIA_API_KEY "nvapi-your-key-here"

    # On Linux/Mac
    export NVIDIA_API_KEY="nvapi-your-key-here"

Step 3.2: Enabling & Configuring MongoDB Atlas Vector Search

MongoDB handles the math required to compare vectors. Vector Search is fully integrated into MongoDB Atlas, but it requires explicit configuration. Note: Your MongoDB Atlas Cluster must be running version 6.0.11+ or 7.0.2+ to support Vector Search.

Important Dimension Match: If you change the model in NVIDIA to nemotron-3-embed-1b or any other model, you must check NVIDIA's documentation to see how many dimensions it outputs (e.g., 4096, 1024, 768). The numDimensions parameter in MongoDB must exactly match the output of the model! Our code currently uses snowflake/arctic-embed-l which outputs 1024 dimensions.
  1. Log In: Access your MongoDB Atlas account.
  2. Navigate to Search: From your Database Deployments view, click on your Cluster, then click the Search tab.
  3. Create Index: Click the green Create Search Index button.
  4. Select Configuration Method: Choose JSON Editor under the "Atlas Vector Search" configuration options, then click Next.
  5. Select Target: In the left panel, select your target Database (e.g., emploismaroc) and the Collection job.
  6. Name the Index: You MUST name the index exactly: vector_index (This string is hardcoded in your AdService.java search pipeline).
  7. Define the JSON Schema: Paste the following JSON configuration into the editor:
    { "fields": [ { "numDimensions": 1024, "path": "embedding", "similarity": "cosine", "type": "vector" } ] }
    Explanation of parameters:
    • numDimensions: 1024 corresponds exactly to the array size returned by NVIDIA.
    • path: "embedding" is the field name we added to the Ad.java model.
    • similarity: "cosine" is the mathematical formula used to measure how close two vectors are (Cosine Similarity is the standard for text embeddings).
  8. Build the Index: Click Next, review your settings, and click Create Search Index. The index status will show as Pending and then Active once it's ready. (This might take a few minutes).
